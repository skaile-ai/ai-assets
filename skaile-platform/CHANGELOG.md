# Changelog — skaile-platform

## [Unreleased]

### Changed
- The `platform-guide` skill moved to `skaile-ai/platform` (`features/platform-guide/`), which embeds it into the backend and ships it with each deploy. `skills/platform-guide/` is removed here; `DOMAIN.md` points at the new home. Edit the guide in the same platform PR as the change it describes.
- `auto-ship` 0.3.0: a new non-negotiable says a platform changeset with a `whats-new:`, `whats-new-highlight:` or `whats-new-agent:` marker carries the guide and capabilities-doc edits in the same PR, or a decline marker with a reason.
- Agent `assistant` (`skaile-assistant`) 1.1.0 moves to `spec_version: "0.2"`. No composition content changes. `knowledge/index.yaml` (empty on purpose) loses its "loaded at session start" description and its unread `retrieval: load_all` block.
- Agent `assistant` (`skaile-assistant`) 1.2.0 declares `memory.blocks` `preferences` (4000 chars), `commitments` (4000) and `learned` (6000), all `scope: user`: a personal assistant remembers per person, never organization-wide. The runner registers the `memory.*` capabilities only when the host advertises `host.memory_store`, so the blocks take effect once the platform ships its memory store; the host can still override the scope per instance (`agents.<id>.memory.scope`). `SOUL.md` gains a "What You Remember" section that says what goes into each block, that in a session with several participants only what the memory's owner says is recorded, and that without `memory.*` the assistant has no memory between sessions. `RULES.md` forbids storing secrets, other people's personal details or anything the user asked to forget in memory, and overwriting a block with `memory.write` without reading it first. The blocks hold what the assistant learns while working; who the user is and how the assistant sounds stay in the host's assistant profile. `docs/agents.md` documents the `host.memory_store` gate and the per-instance scope override.
